# InferenceX chart metric source audit / 图表指标来源核对

[English](SOURCE_METRICS.md) | [中文](SOURCE_METRICS_zh.md)

The plotting source is the separate public [InferenceX-app repository](https://github.com/SemiAnalysisAI/InferenceX-app), linked by InferenceX README.md:34. The read-only local clone is pinned at `b4b72f4f39ad6148f3477dcf67eb6a77257e7bb9`.

| E2EL appendix x | `median_e2el_ms / 1000` → `median_e2el`, seconds | [producer](https://github.com/SemiAnalysisAI/InferenceX/blob/8979f7c4cdd2946a02b459d5e62018e41bc02405/infx/results/fixed_sequence.py#L203-L207), [frontend](https://github.com/SemiAnalysisAI/InferenceX-app/blob/b4b72f4f39ad6148f3477dcf67eb6a77257e7bb9/packages/app/src/components/inference/metric-registry.ts#L701-L708) |

`infx/bench_serving/benchmark_serving.py:465-473, 509-530` defines TPOT per successful request as `(latency - TTFT) / (output_len - 1)`, E2EL from request latency, and each median with `np.median`; output throughput counts generated output tokens divided by benchmark wall duration. For the completions API, latency runs from request start to the last received choices chunk (`infx/bench_serving/backend_request_func.py:258-303`), and includes TTFT. Our ISL/OSL caps are sampled at ratio0.8, not fixed observed lengths.

The website fixes these x metrics to median for fixed-sequence workloads: [resolveXAxisField.ts:37-67](https://github.com/SemiAnalysisAI/InferenceX-app/blob/b4b72f4f39ad6148f3477dcf67eb6a77257e7bb9/packages/app/src/components/inference/utils/resolveXAxisField.ts#L37-L67). It offers Interactivity, E2E Latency, and TTFT, not a direct TPOT x option: `XAxisModeSelector.tsx:15-24`. Interactivity is its fixed-sequence default x; its current default y is cost `y_tokensPerDollarH` (`lib/url-state.ts:126`), so output/GPU must be described as our selected website metric, not the website default.

The experiment has PP=PCP=1 and metadata gpu_count=TP. `infx/results/topology.py:20-22` computes physical allocation as TP×PP×PCP; EP shares the allocation. Do not multiply DP/EP into GPU normalization.

Series frontier point selection independently matches [chart-utils.ts:624-687](https://github.com/SemiAnalysisAI/InferenceX-app/blob/b4b72f4f39ad6148f3477dcf67eb6a77257e7bb9/packages/app/src/lib/chart-utils.ts#L624-L687), including the historical E2EL equal-y tie rule. Global frontier independently matches [global-pareto.ts:25-62](https://github.com/SemiAnalysisAI/InferenceX-app/blob/b4b72f4f39ad6148f3477dcf67eb6a77257e7bb9/packages/app/src/components/inference/utils/global-pareto.ts#L25-L62), which removes dominated and tied coordinate duplicates. E2EL minimizes x and maximizes y; interactivity maximizes both. The historical names `upper_left` and `upper_right` are opposite intuitive numeric x directions: `ScatterGraph.tsx:1493-1524` explicitly documents this. Source code takes precedence over a stale direction table in `docs/d3-charts.md`.

Static plots preserve all successful observations, separate workload/runtime/run series while pooling topology choices within each arm, and enable a global frontier with a dotted line and observed-vertex rings. Global straight segments follow the website. Per-series colored lines use straight guides instead of the website's D3 monotone interpolation (`ScatterGraph.tsx:2331-2335`); this adaptation is disclosed. Labels always show C and TP/DP/EP per user request, extending the website's optional concurrency + advanced topology labels (`ui/point-label.ts:4-12`). No claims about unmeasured intermediate points, same-runtime kernel speedup, or latency SLO are made.

Its unofficial overlay at `1080-1110` groups `hwKey + precision + runIndex`. TP/DP/EP and concurrency are not series keys. `chart-utils.ts:264-289` builds hwKey from hardware, framework and speculation. The static experiment matches this by pooling TP/DP/EP choices within each backend/runtime/run while retaining complete per-point topology and client concurrency.
